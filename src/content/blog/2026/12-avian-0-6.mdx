**Avian Physics 0.6** has been released! 🪶

[**Avian**](https://github.com/Jondolf/avian) is an ECS-based 2D and 3D physics engine for [Bevy](https://bevyengine.org/),
a refreshingly simple data-driven game engine built in Rust. Avian prioritizes ergonomics and modularity,
with a focus on providing a native ECS-driven user experience.

Check out the [GitHub repository](https://github.com/Jondolf/avian) and the [introductory post](https://joonaa.dev/blog/06/avian-0-1) for more details.

## Highlights

**Avian 0.6** brings several major optimizations and features:

- **Move-and-slide**: Avian now supports move-and-slide, the fundamental movement and collision algorithm used for a Kinematic Character Controller (KCC).
- **Joint motors**: Revolute joints and prismatic joints now support motors with both velocity and position control.
- **BVH broad phase**: Broad phase collision detection now uses [OBVHS](), massively improving performance for large scenes and static geometry.

The migration guide and a more complete changelog can be found on [GitHub](https://github.com/Jondolf/avian/releases/tag/v0.6.0).

## Move-and-Slide

<ReleaseNoteMetadata authors={['janhohenheim', 'Jondolf', 'unpairedbracket', 'UndefinedBHVR']} prs={[894]} repo={AVIAN_URL} />

For years(!) now, a very common pain point for users of Avian has been the lack of a Kinematic Character Controller (KCC).
There have been some dynamic character controllers (`bevy_tnua`), and numerous scattered implementations from different people,
but no concentrated effort on a built-in solution.

This has been due to several factors:

1. Character controllers are very game-specific and difficult to generalize
2. Users can already build their own character controllers, no built-in integration is strictly necessary
3. Other work for the core Avian has been a higher priority for me

However, as Avian and its community has grown, it has became clearer that official character controller functionality
is strongly desired. KCCs are integral to the majority of games, but notoriously difficult to get right.
While we cannot cater to the needs of every character controller, we can and should support the most fundamental
and commonly used features, to form a foundation to build your own opinionated KCC upon.
